
# تحويل المنصة إلى تطبيق Windows مستقل (.exe) مع قاعدة بيانات محلية

## النتيجة النهائية
ملف تثبيت `.exe` لويندوز يحتوي على:
- واجهة التطبيق كاملة (نفس الشكل الحالي).
- قاعدة بيانات محلية مدمجة (لا تحتاج إنترنت).
- تسجيل دخول محلي (admin افتراضي).
- يعمل تلقائياً عند تشغيله، بدون الحاجة لتنصيب PostgreSQL أو Supabase أو Docker.

## الطريقة المختارة

استخدام **Electron** + **PGlite** (PostgreSQL يعمل داخل التطبيق نفسه بدون خادم) + طبقة محول `db-client` تستبدل `supabase-js` بقاعدة بيانات محلية عند العمل في وضع سطح المكتب.

لماذا PGlite؟ لأنه يدعم نفس صياغة PostgreSQL الموجودة في migrations الحالية، فلا نحتاج إعادة كتابة الجداول والسياسات.

## ما الذي سيتم بناؤه

### 1. طبقة قاعدة البيانات المحلية
- إنشاء `src/integrations/local-db/` يحتوي:
  - `pglite-client.ts`: تهيئة PGlite وتطبيق جميع ملفات migrations عند أول تشغيل.
  - `local-supabase-adapter.ts`: محاكاة واجهة `supabase.from().select().insert()...` مقابل PGlite.
  - `local-auth.ts`: مصادقة محلية بسيطة (admin/employee/viewer) مع تشفير كلمات المرور.
- تعديل `src/integrations/supabase/client.ts` لاختيار العميل (سحابي أو محلي) حسب متغير `VITE_APP_MODE=desktop`.

### 2. غلاف Electron
- إنشاء `electron/main.cjs` لفتح نافذة بحجم كامل وتحميل `dist/index.html`.
- إنشاء `electron/preload.cjs` لتمرير مسار حفظ البيانات (AppData) إلى الواجهة.
- ضبط `vite.config.ts` على `base: './'` (مطلوب لـ Electron).

### 3. الميزات التي تحتاج اتصال
الميزات التالية ستظهر رسالة "تتطلب إنترنت" في وضع سطح المكتب:
- البحث الحكومي (gov-search).
- استخراج المستندات بالذكاء الاصطناعي (OCR).
- مساعد الذكاء الاصطناعي.
الباقي (الأرشيف، الملفات، الاجتماعات، الاستدعاءات، الأرشيف القانوني، النسخ الاحتياطي JSON…) يعمل كاملاً offline.

### 4. سكريبت البناء
سكريبت `scripts/build-windows-exe.ps1` ينفذ:
1. `npm run build` (بناء الواجهة).
2. `electron-packager` لتجميع كل شيء.
3. إنتاج `release/OPVM-Setup.exe` جاهز للتنصيب.

### 5. النسخ الاحتياطي والاستيراد
نظام النسخ JSON الحالي يبقى كما هو ويعمل لنقل البيانات بين:
- النسخة السحابية ← النسخة المكتبية (وبالعكس).
- جهاز إلى جهاز.

## القيود الواقعية

1. **PGlite يعمل في المتصفح/Electron** ويخزن البيانات في مجلد AppData للمستخدم. آمن، لكن لا يمكن لعدة مستخدمين على شبكة الوصول لنفس البيانات في نفس الوقت. لو احتجت ذلك مستقبلاً نحتاج خادم PostgreSQL منفصل.
2. **RLS لا يُطبَّق** في النسخة المحلية بنفس الطريقة، نعتمد على التحقق من الدور في الواجهة (نفس النمط الحالي).
3. **حجم ملف التنصيب**: ~150-200 MB (طبيعي لـ Electron + PGlite).
4. **البناء النهائي للـ .exe لا يمكن تنفيذه من داخل Lovable** — هذا الإعداد يجهّز الكود والسكربتات، ثم تشغّل أنت الأمر التالي على جهاز Windows:
   ```
   npm install
   npm run build:windows
   ```
   وسيظهر الملف في `release/`.

## الخطوات (بترتيب التنفيذ)

1. تثبيت الحزم: `electron`, `@electron/packager`, `@electric-sql/pglite`.
2. إنشاء طبقة `local-db` (PGlite + adapter + auth).
3. تعديل `supabase/client.ts` لاختيار العميل.
4. إنشاء `electron/main.cjs` + `preload.cjs`.
5. تعديل `vite.config.ts` (`base: './'` لوضع desktop فقط).
6. إضافة سكريبتات `package.json`: `build:desktop`, `build:windows`.
7. كتابة سكريبت PowerShell للبناء.
8. تحديث `README` بتعليمات التنصيب على Windows.

## بدائل لم أخترها (ولماذا)

- **SQLite بدلاً من PGlite**: يتطلب إعادة كتابة كل الـ migrations والاستعلامات.
- **PostgreSQL محلي + Docker**: يصعّب التنصيب على المستخدم النهائي ويحتاج صلاحيات admin.
- **Tauri بدلاً من Electron**: أخف لكن يتطلب Rust toolchain ويعقّد البناء.
